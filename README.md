# AIChatReviewer – Система анализа чатов

Проект предназначен для автоматического сбора, анализа и визуализации обсуждений из социальных сетей (в настоящее время ВКонтакте).  
Собранные данные обрабатываются с помощью LLM (через YandexGPT), выделяются проблемы, группируются, и строится график динамики голосов по категориям во времени.

## Структура проекта

- `main.py` – точка входа, загружает конфигурацию и последовательно запускает компоненты.
- `agent.py` – классы `AliceAIAgent` (обёртка для YandexGPT) и `DataAnalyzer` (многошаговый анализ сообщений).
- `visualizer.py` – класс `Visualizer` для построения графиков по результатам анализа.
- `config.json` – основной файл конфигурации.
- `requirements.txt` – список зависимостей.
- `parser.py` и `exporter.py` – модули для сбора данных из ВК (будут добавлены отдельно).

## Установка

1. Клонируйте репозиторий.
2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
3. Получите API‑ключ YandexGPT и сохраните его в файл `api_key.json` в формате:
   ```json
   { "api_key": "ваш_ключ" }
   ```
4. (Опционально) Для сбора данных из ВК потребуется токен сообщества, он указывается в конфигурации.

## Конфигурация

Все настройки задаются в файле `config.json`.  
Общий уровень логирования (`shared.logging_level`):
- `0` – только ошибки
- `1` – основные этапы с прогресс-барами
- `2` – подробная отладочная информация

### Секция `parser`
Включает/отключает сбор данных из ВК. Параметры:
- `vk_token`, `vk_api_version`, `groups_file`, `db_file`, `request_delay`, `start_date`, `end_date`, `days_back`.

### Секция `analyzer`
Настройки анализатора (модель, ограничения выборки, включение шагов):
- `api_key_file` – путь к файлу с ключом Yandex.
- `agent_id` – идентификатор каталога в Yandex Cloud.
- `system_prompt_file`, `system_prompt_file_2` – файлы с системными промптами для первого и второго агентов.
- `base_url`, `model_name` – параметры модели (по умолчанию YandexGPT).
- `max_chats`, `max_messages_per_chat` – ограничения на входные данные.
- `max_chain_packets`, `max_isolated_packets`, `max_chain_packet_messages`, `isolated_packet_size` – параметры группировки сообщений.
- `max_retries` – число повторных попыток при ошибках.
- `problems_per_packet` – размер пакета (количество проблем) при рекурсивной агрегации на втором шаге (по умолчанию 200).
- `steps` – какие шаги анализа выполнять:
  - `step1_analyze_chats` – первичный анализ сообщений,
  - `step2_aggregate_results` – агрегация проблем в категории (рекурсивная),
  - `step3_backward_mapping` – обратный проход для сбора полных данных.

### Секция `visualizer`
Параметры построения графиков:
- `data_file` – путь к JSON с результатами 3‑го шага (по умолчанию `agent_data/analysis_step_3.json`).
- `interval_days` – длина интервала в днях для агрегации по времени.
- `start_date`, `end_date` – ограничение временного диапазона (формат `YYYY-MM-DD`).
- `save_path` – файл для сохранения графика (PNG).
- `show` – показывать ли график на экране.
- `min_percent_threshold` – порог в % от среднего: значения ниже него удаляются (не отображаются).
- `smoothing_window` – окно сглаживания: количество значимых интервалов слева и справа, участвующих в скользящем среднем (0 – отключено).

## Запуск

```bash
python main.py
```

При включённом парсере будут загружены сообщения из ВК и сохранены в базу данных, затем экспортированы в `output.json` (этот файл должен быть переименован или указан в `shared.chats_file`).  

При включённом анализаторе последовательно выполняются шаги:

1. **Анализ сообщений** – выделение проблем из каждого пакета сообщений. Результат сохраняется в `analysis_step_1.json`.
2. **Агрегация проблем в категории** – рекурсивное разбиение списка проблем на пакеты размера `problems_per_packet` с последующим группированием. Результат сохраняется в `analysis_step_2.json`.
3. **Обратный проход** – сопоставление итоговых категорий с исходными сообщениями, подсчёт уникальных голосов. Результат сохраняется в `analysis_step_3.json`.

После завершения анализа визуализатор строит график динамики голосов по категориям.

## Результаты

- `analysis_step_1.json` – проблемы, найденные в каждом пакете сообщений.
- `analysis_step_2.json` – итоговые категории проблем и связь с исходными проблемами (по номерам).
- `analysis_step_3.json` – категории с полными данными участников и подсчитанным количеством голосов.
- График (например, `votes_14-days-n.png`) – отображает изменение активности по категориям во времени.

## Примечания

- Для работы анализатора необходимо наличие файлов с системными промптами (пути задаются в конфиге).
- При использовании парсера убедитесь, что файл `groups.txt` содержит идентификаторы сообществ ВК (по одному на строку).
- Все промежуточные и итоговые файлы сохраняются в папку `agent_data/` (создаётся автоматически).
