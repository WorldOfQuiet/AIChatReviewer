# AIChatReviewer

Инструмент для автоматизированного анализа текстовых чатов с использованием языковых моделей (LLM). Проект предназначен для выявления проблем, о которых пишут участники чата, группировки их по темам и формирования структурированного отчёта с указанием конкретных сообщений.

## Возможности

- Загрузка чатов из JSON-файла в заданном формате.
- Разбиение сообщений на логические пакеты (по цепочкам ответов) для обработки моделью.
- Двухэтапный анализ:
  1. Первый агент выделяет отдельные проблемы и привязывает к ним номера сообщений.
  2. Второй агент объединяет похожие проблемы в итоговые категории.
- Обратный проход – сбор полных сообщений (с автором, датой, медиа) по каждой категории.
- Гибкая настройка через `config.json` (количество обрабатываемых чатов, сообщений, пакетов, повторных попыток и т.д.).
- Логирование с тремя уровнями детализации.
- Возможность сменить используемую модель через параметры `base_url` и `model_name`.

## Требования

- Python 3.8 или выше
- Установленные зависимости: `requests`

## Установка

1. Склонируйте репозиторий:
   ```bash
   git clone https://github.com/yourusername/AIChatReviewer.git
   cd AIChatReviewer
   ```

2. Установите зависимости:
   ```bash
   pip install requests
   ```

3. Подготовьте файл с API-ключом (например, `api_key.json`):
   ```json
   {
     "api_key": "ваш_ключ_яндекс_облака"
   }
   ```

4. Создайте файл с исходными чатами (по умолчанию `agent_data/chats.json`). Формат описан ниже.

## Конфигурация

Все настройки задаются в файле `config.json` в корне проекта. Пример:

```json
{
  "shared": {
    "chats_file": "agent_data/chats.json"
  },
  "parser": {
    "enabled": true,
    "preferences": {}
  },
  "analyzer": {
    "enabled": true,
    "preferences": {
      "api_key_file": "api_key.json",
      "agent_id": "b1ghrgitp2eqakb9c44o",
      "system_prompt_file": "agent_data/analysis_of_chat(instructions_3).txt",
      "system_prompt_file_2": "agent_data/analysis_of_results.txt",
      "base_url": "https://llm.api.cloud.yandex.net/foundationModels/v1/completion",
      "model_name": "aliceai-llm/latest",
      "logging_level": 2,
      "max_chats": 1,
      "max_messages_per_chat": 2000,
      "max_packets": 10,
      "max_packet_messages": 50,
      "isolated_packet_size": 400,
      "max_retries": 3,
      "steps": {
        "step1_analyze_chats": true,
        "step2_aggregate_results": true,
        "step3_backward_mapping": true
      }
    }
  }
}
```

### Описание параметров

#### Общая секция `shared`
- `chats_file` – путь к JSON-файлу с чатами (см. формат ниже).

#### Секция `analyzer.preferences`
- `api_key_file` – путь к файлу с API-ключом.
- `agent_id` – идентификатор каталога в Яндекс.Облаке (используется в `modelUri`).
- `system_prompt_file` – файл с системным промптом для первого агента (анализ чата).
- `system_prompt_file_2` – файл с системным промптом для второго агента (агрегация).
- `base_url` – базовый URL API (можно заменить для использования другой модели).
- `model_name` – имя модели (например, `aliceai-llm/latest`).
- `logging_level` – уровень логирования: 0 – отключено, 1 – основные этапы, 2 – подробно.
- `max_chats` – максимальное количество чатов для обработки (берутся последние).
- `max_messages_per_chat` – сколько последних сообщений брать из каждого чата.
- `max_packets` – максимальное число пакетов для обработки (последние).
- `max_packet_messages` – максимальное число сообщений в одном пакете (последние).
- `isolated_packet_size` – размер пакета для изолированных сообщений (не входящих в цепочки ответов).
- `max_retries` – количество повторных попыток при ошибке запроса к модели.
- `steps` – какие шаги выполнять (все включены по умолчанию).

## Формат входного файла чатов

Файл должен представлять собой JSON-массив объектов, каждый из которых описывает один чат:

```json
[
  {
    "chat_id": 0,
    "chat_name": "Название чата",
    "messages": [
      {
        "id": 0,
        "text": "Текст сообщения",
        "author": "ivan_petrov",
        "media": ["photo1.jpg", "photo2.jpg"],
        "reply_to": -1,
        "date": 1770127214
      },
      ...
    ]
  }
]
```

Поле `media` может быть пустым массивом. `reply_to` указывает на `id` сообщения, на которое дан ответ, или -1.

## Запуск

```bash
python main.py
```

Или, если основной код находится в `agent.py` (как в текущей версии):

```bash
python agent.py
```

Программа выполнит шаги в соответствии с настройками и создаст в папке `agent_data` файлы:
- `analysis_step_1.json` – результаты первого агента (список проблем по каждому пакету).
- `analysis_step_2.json` – результаты второго агента (итоговые категории с номерами исходных проблем).
- `analysis_step_3.json` – финальный отчёт с полными сообщениями по каждой категории.

## Логирование

В зависимости от уровня `logging_level` вывод может быть:
- **0** – только ошибки (если есть).
- **1** – основные этапы и общая информация.
- **2** – подробный вывод, включая текст запросов, ответы модели, предупреждения.

## Шаги анализа

1. **Шаг 1 (анализ чатов)**
   - Загружаются чаты, группируются по цепочкам ответов.
   - Каждый пакет отправляется первому агенту.
   - Агент выделяет проблемы и возвращает список с названиями и списками номеров сообщений.
   - Результат сохраняется в `analysis_step_1.json`.

2. **Шаг 2 (агрегация)**
   - Все проблемы из шага 1 преобразуются в строки вида `номер | название | число голосов`.
   - Этот список отправляется второму агенту.
   - Агент группирует проблемы в категории и возвращает массив объектов с названием категории и списком номеров проблем.
   - Результат сохраняется в `analysis_step_2.json`.

3. **Шаг 3 (обратный проход)**
   - Загружаются исходные чаты и результаты предыдущих шагов.
   - Для каждой категории собираются уникальные сообщения (по номерам из `analysis_step_1.json`).
   - Формируется итоговый отчёт с полной информацией о каждом сообщении (автор, текст, медиа, дата).
   - Сохраняется в `analysis_step_3.json`.

## Примечания

- Для работы требуется действующий API-ключ Яндекс.Облака и доступ к модели.
- При смене модели убедитесь, что она поддерживает формат запроса `gpt://<catalog_id>/<model_name>`.
- Парсер (`parser` в конфиге) пока не реализован и зарезервирован для будущего использования.
