# AIChatReviewer – Система анализа чатов

Проект предназначен для автоматического сбора, анализа и визуализации обсуждений из социальных сетей (ВКонтакте).
Собранные данные обрабатываются с помощью LLM (через OpenAI-совместимый API), выделяются проблемы, группируются, и строится график динамики голосов по категориям во времени.

├── .gitignore

│   ├── __init__.py

│   ├── config.py           – загрузка конфигурации
│   └── data_processor.py   – обработка данных, парсинг ответов модели
│
├── analyzer/
│   ├── __init__.py
│   ├── base_analyzer.py    – базовый класс анализатора
│   ├── data_analyzer.py    – оркестратор трёх шагов анализа
│   ├── step1_analyzer.py   – шаг 1: выделение проблем из сообщений
│   ├── step2_aggregator.py – шаг 2: агрегация проблем в категории
│   └── step3_mapper.py     – шаг 3: обратный проход с подсчётом голосов

## Установка

1. Клонируйте репозиторий.
2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
3. API-ключ уже указан в `config.json` (секция `analyzer.preferences.api_key`).
4. (Опционально) Для сбора данных из ВК потребуется токен сообщества, он указывается в `config.json` (секция `parser.preferences.vk_token`).

## Конфигурация

Все настройки задаются в файле `config.json`.

Общий уровень логирования (`shared.logging_level`):
- `0` – только ошибки
- `1` – прогресс-бары (tqdm), без логов httpx/openai
- `2` – подробная отладочная информация

### Секция `parser`
Включает/отключает сбор данных из ВК. Параметры:
`vk_token`, `vk_api_version`, `groups_file`, `db_file`, `request_delay`, `start_date`, `end_date`, `days_back`.

### Секция `analyzer`
Настройки анализатора (модель, ограничения выборки, включение шагов):
- `api_key` – ключ API для OpenAI-совместимого провайдера.
- `system_prompt_file`, `system_prompt_file_2` – файлы с системными промптами (на английском, ответ ожидается на русском).
- `base_url` – URL API (по умолчанию `https://routerai.ru/api/v1`).
- `model_name` – модель (по умолчанию `deepseek/deepseek-v4-flash`).
- `max_chats`, `max_messages_per_chat` – ограничения на входные данные.
- `max_chain_packets`, `max_isolated_packets`, `max_chain_packet_messages`, `isolated_packet_size` – параметры группировки сообщений.
- `max_retries` – число повторных попыток при ошибках.
- `problems_per_packet` – размер пакета при рекурсивной агрегации на шаге 2.
- `steps` – какие шаги анализа выполнять:
  - `step1_analyze_chats` – первичный анализ сообщений,
  - `step2_aggregate_results` – агрегация проблем в категории (рекурсивная),
  - `step3_backward_mapping` – обратный проход для сбора полных данных.

### Секция `visualizer`
Параметры построения графиков:
- `data_file` – путь к JSON с результатами 3‑го шага.
- `interval_days` – длина интервала в днях для агрегации по времени.
- `start_date`, `end_date` – ограничение временного диапазона.
- `save_path` – файл для сохранения графика (PNG).
- `show` – показывать ли график на экране.
- `min_percent_threshold` – порог в % от среднего: значения ниже него удаляются.
- `smoothing_window` – окно сглаживания (0 – отключено).

## Запуск

```bash
python main.py
```

При включённом парсере будут загружены сообщения из ВК и сохранены в базу данных, затем экспортированы в JSON.

При включённом анализаторе последовательно выполняются шаги:

1. **Анализ сообщений** – сообщения группируются в цепочечные и изолированные пакеты, авторы анонимизируются, ID заменяются на локальные индексы (1, 2, 3...). Каждый пакет отправляется LLM для выделения проблем. После ответа локальные индексы восстанавливаются в абсолютные. Результат сохраняется в `analysis_step_1.json`.
2. **Агрегация проблем в категории** – рекурсивное разбиение списка проблем на пакеты с последующим группированием через LLM. Результат сохраняется в `analysis_step_2.json`.
3. **Обратный проход** – сопоставление итоговых категорий с исходными сообщениями, подсчёт уникальных голосов. Результат сохраняется в `analysis_step_3.json`.

После завершения анализа визуализатор строит график динамики голосов по категориям.

## Результаты

- `analysis_step_1.json` – проблемы, найденные в каждом пакете сообщений.
- `analysis_step_2.json` – итоговые категории проблем и связь с исходными проблемами.
- `analysis_step_3.json` – категории с полными данными участников и подсчитанным количеством голосов.
- График (например, `votes_14-days-n.png`) – отображает изменение активности по категориям во времени.

## Примечания

- Для работы анализатора необходимы файлы с системными промптами (пути задаются в конфиге).
- Промпты написаны на английском, модель возвращает ответы на русском.
- Режим thinking у модели принудительно отключён (`thinking: {"type": "disabled"}`).
- Температура модели по умолчанию `0.0` для детерминированных ответов, макс. токенов — `16000`.
- При использовании парсера убедитесь, что файл `groups.txt` содержит идентификаторы сообществ ВК (по одному на строку).
- Все промежуточные и итоговые файлы сохраняются в папку `agent_data/`.
