# AIChatReviewer

```markdown
# Анализ чатов жителей города

Данный скрипт (`agent.py`) реализует многошаговый pipeline для анализа логов переписки жителей, выделения проблем, их группировки и итогового формирования структурированного отчёта. Ниже описаны все шаги обработки и форматы промежуточных и итоговых JSON-файлов.

## Входные данные

Каждый чат представлен JSON-файлом вида:
```json
{
  "chat_id": 0,
  "chat_name": "Проблемы города N",
  "messages": "0 | Ул. Мира, 10 — огромная яма на дороге... | ivan_petrov | [photos/ivan_1.jpg] | -1\n1 | ..."
}
```
- `chat_id` – уникальный идентификатор чата.
- `chat_name` – название чата.
- `messages` – многострочная строка, где каждая строка соответствует одному сообщению в формате:
  ```
  <номер> | <текст> | <автор> | [<список медиа>] | <номер ответа>
  ```
  (подробная расшифровка приведена в файле `analysis_of_chat(instructions_3).txt`).

## Используемые системные промпты

- `analysis_of_chat(instructions_3).txt` – промпт для первого агента, который анализирует сырой лог чата и выделяет проблемы с привязкой к сообщениям.
- `analysis_of_results.txt` – промпт для второго агента, который группирует проблемы из первого шага в более крупные тематические категории.

## Шаг 1: Анализ исходных чатов

**Вход:** один или несколько JSON-файлов чатов (`chat_*.json`).

**Действия:**
- Каждый чат разбивается на части по **400 сообщений** (для обхода ограничений модели).
- Для каждой части вызывается первый агент с промптом `analysis_of_chat(instructions_3).txt`.
- Агент возвращает JSON-список проблем, каждая проблема содержит:
  - `name` – название проблемы (сформулированное агентом);
  - `complaints` – список номеров сообщений, относящихся к этой проблеме (по одному от каждого участника).
- В скрипте к каждой проблеме добавляется поле `count = len(complaints)`.

**Выход:** `analysis_step_1.json` – список объектов вида:
```json
[
  {
    "chat_id": 0,
    "chat_name": "Проблемы города N (часть 1)",
    "analisis_result": [
      {
        "name": "проблемы с дорогами (ямы, колдобины)",
        "count": 28,
        "complaints": [0, 1, 2, 3, 20, 21, 22, 23, ...]
      },
      ...
    ]
  },
  ...
]
```

## Шаг 2: Агрегация проблем через второго агента

**Вход:** `analysis_step_1.json`.

**Действия:**
- Из всех записей `analisis_result` формируется таблица строк вида:
  ```
  <номер проблемы> | <название проблемы> | <число голосов>
  ```
  (нумерация сквозная по всем частям всех чатов).
- Эта таблица отправляется второму агенту с промптом `analysis_of_results.txt`.
- Агент группирует похожие проблемы в тематические категории и возвращает список групп, где каждая группа содержит:
  - `name` – название группы;
  - `complaints` – **номера проблем** (из таблицы), которые вошли в эту группу.

**Выход:** `analysis_step_2.json` – список групп:
```json
[
  {
    "name": "Дороги и транспортная инфраструктура",
    "complaints": [1, 6, 8, 9, 10, 22, 30]
  },
  {
    "name": "Уборка и содержание территорий",
    "complaints": [2, 12, 16, 19]
  },
  ...
]
```

## Шаг 3: Подсчёт итоговых голосов

**Вход:** `analysis_step_2.json`.

**Действия:**
- Для каждой группы из шага 2 суммируются **элементы списка `complaints`** (сами номера проблем).  
  Важно: здесь суммируются именно числовые значения, а не длины списков. Это даёт итоговое количество голосов (сообщений) по каждой группе.

**Выход:** `analysis_step_3.json` – словарь вида:
```json
{
  "Дороги и транспортная инфраструктура": 86,
  "Уборка и содержание территорий": 49,
  "Финансовые и трудовые вопросы": 67,
  ...
}
```

## Шаг 4: Обратный проход с участниками

**Вход:** `analysis_step_1.json`, `analysis_step_2.json`, `analysis_step_3.json` и исходные чаты (`chat_*.json`).

**Действия:**
- Восстанавливается полный список всех проблем, которые подавались на вход второму агенту (в порядке нумерации). Для этого используется `analysis_step_1.json`.
- Для каждой группы из `analysis_step_2.json`:
  - По номерам проблем из поля `complaints` находятся соответствующие записи из шага 1.
  - Из этих записей извлекаются **названия исходных проблем** и собираются в поле `complaints` (теперь это список строк, а не чисел).
  - Из номеров сообщений (поля `complaints` в шаге 1) извлекаются полные данные каждого сообщения (номер, текст, автор, медиа, reply_to) из исходных чатов. Эти данные собираются в поле `participants` (без дубликатов).
  - Добавляется поле `total_votes` из шага 3.

**Выход:** `analysis_step_4.json` – итоговый структурированный отчёт:
```json
[
  {
    "name": "Дороги и транспортная инфраструктура",
    "total_votes": 86,
    "complaints": [
      "проблемы с дорогами (ямы, колдобины)",
      "транспортные проблемы",
      ...
    ],
    "participants": [
      {
        "num": 0,
        "text": "Ул. Мира, 10 — огромная яма на дороге, провалился колесом! Вот несколько фото:",
        "author": "ivan_petrov",
        "media": ["photos/ivan_1.jpg", "photos/ivan_2.jpg", "photos/ivan_3.jpg"],
        "reply_to": -1
      },
      ...
    ]
  },
  ...
]
```

## Примечания

- Шаги 1 и 2 по умолчанию **закомментированы** в `agent.py`, так как предполагается, что файлы `analysis_step_1.json` и `analysis_step_2.json` уже получены. Для повторного запуска полного цикла необходимо раскомментировать соответствующие блоки.
